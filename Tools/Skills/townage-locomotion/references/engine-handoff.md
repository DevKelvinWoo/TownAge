# Animation handoff checks

- Confirm Blender MCP is live before editing and Unreal MCP is live before integration. Both are registered on this host, but Blender may be closed. Never interpret registration as a successful editor tool call.
- Source uses an 18-bone deform hierarchy; the Unreal skeleton may include an additional FBX armature wrapper. Inspect both actual hierarchies and preserve the existing production root name (current TownKeeper exporter uses Armature_008). Repeated Blender suffixes can break skeleton compatibility.
- Current model is under ArtSource/Characters/Main/Revision05 and native code references /Game/Characters/Main/TownKeeper/FinalCharacter05/SK_TownKeeper_Reference05. Its compatible animations and Blend Space are in FinalCharacter05/Animations. Do not switch back to archived prototypes. Keep animation authoring separate from the model source.
- Revision05 changed bone reference positions for shorter body proportions. Its walk retains the approved28-frame/64cm gait through recomputed IK on the new leg lengths. Original Revision04 motion sources and the unapproved IdleDraft01 must be adapted and reviewed against the current skeleton before future integration; matching bone names alone does not establish compatibility.
- Confirm 170cm source/engine size unless the user requests another size, object and armature scale1, matching axis conversion and FBX unit factor1. Verify animation-only import does not introduce root-scale100 or alter the reference pose.
- Basic locomotion stays in-place. Inspect root translations over the entire take and preserve a stationary ground root while allowing the pelvis to move. Do not enable Root Motion from Everything as a default multiplayer solution. Special root-driven actions require a separate gameplay/network design.
- Export the requested named takes only. Do not use all-actions export blindly or include rest-pose tests. Bake control constraints to keys, inspect interpolation/loop endpoints, and roundtrip the FBX before production import.
- Resolve actual UE AnimSequence, Blend Space and Anim Blueprint tools/schemas at runtime. Import to a dedicated animation folder bound to the retained Skeleton; do not create an accidental new Skeleton per clip.
- Start Blend Space samples at actual intended speeds: Standing0 and approved Walk68.5714cm/s currently. Sprint movement is440cm/s but has no approved sprint clip yet; do not pretend capped fast-walk playback is a finished sprint. Match cadence/stride with game displacement and inspect sliding. The rotate-to-movement controller initially needs forward locomotion rather than strafing clips.
- Attach the Anim Blueprint to the native playable mesh or its intended editable class as well as any requested placement BP. Save and reload; inspect newly spawned PIE pawns and replicated proxies.
- In UE5.8, assigning Blend Space sample_data alone may not rebuild interpolation data. Validate and resample before saving, then query actual endpoint sample weights. Leave a small axis-range margin around sample speeds: float axis limits can reject double-precision samples at an apparently equal maximum.
- If integration uses the engine's native single-node AnimInstance with a Blend Space rather than an editable Anim Blueprint, state that explicitly. Verify actual skinned bone motion, not only a changing playback timestamp.

Use current installed-version docs for exact APIs.
